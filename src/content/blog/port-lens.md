平时开发里，有一类命令我反复在用，但一直觉得不够顺手，于是干脆把它们整理成了一个小工具：`Port Lens`，命令名就叫 `ports`。

起因很简单。开发时最常见、也最打断节奏的问题之一，就是服务起不来，然后终端甩来一句“端口已被占用”。

这时候当然不是没办法解决。你可以用 `lsof` 查，也可以继续配合 `grep`、`kill`、`pkill` 往下处理。但真实的问题是，这套流程虽然不复杂，却很不顺手，而且每次都要重新把命令和参数从脑子里翻出来一遍。

我想做的，其实不是重新发明什么端口管理系统，而是把这件高频小事，收拢成一个更直接的入口：输入 `ports`，立刻看见是谁占了端口、它属于哪个项目、是不是该关掉，以及要怎么处理。

## 它解决的是什么问题

开发者遇到的端口问题，往往不是“不会查”，而是“查起来很碎”。

比如：

- 终端提示 `3000` 或 `5173` 被占用了，但你不知道是哪个服务还活着。
- 你能想起 `lsof -i` 这类命令，但总得重新确认参数。
- 好不容易找到 PID，接下来还要手动判断该不该 `kill`。
- 有些进程来自昨天开的本地项目，有些是 Docker、Node、Python、Rust 服务，终端输出本身并不直观。

`Port Lens` 处理的，就是这类“技术上不难，但经常打断节奏”的小问题。

## 最核心的体验：先看清，再动手

最常用的命令只有一条：

```bash
ports
```

它会列出当前本地常见的监听端口，并把关键信息整理成表格：端口、进程、PID、项目路径、技术栈、运行时间，一眼就能看明白。

![](https://img.alicdn.com/imgextra/i2/O1CN01F30wi01QblHh4l8Ou_!!6000000001995-2-tps-1576-830.png)

默认输出会尽量过滤掉一些桌面和系统层面的噪声，优先保留开发时真正关心的监听项。如果你就是想把所有监听都翻出来看，也可以：

```bash
ports --all
```

![](https://img.alicdn.com/imgextra/i2/O1CN012Vnm1u1Gc5PExi50O_!!6000000000642-2-tps-1752-1776.png)

这类默认值对我来说很重要。因为大部分时候，我不是想做系统排障，而只是想快速回答一个问题：现在这个端口到底是谁占的。

## 不只是查端口，还能继续追下去

如果只想看某一个端口，可以直接带端口号：

```bash
ports 8000
```

![](https://img.alicdn.com/imgextra/i4/O1CN017Jwquj1COZFowfCdT_!!6000000000071-2-tps-1520-336.png)

这里给出的不只是“有一个 PID 正在监听”，还会继续展示更完整的上下文，比如进程树、工作目录、Git 分支、内存占用等。对本地开发来说，这些信息比单独一个 PID 更有判断价值，因为你能更快确认它是不是刚才那个项目、是不是另一个终端窗口留下来的服务，或者是不是某个容器转发出来的端口。

看清楚之后，接下来的处理也可以直接在同一个工具里做。

比如关掉指定端口：

```bash
ports kill 3000 5173
```

也支持按 PID 结束进程；如果确实需要强制结束，也有 `-f` 可用来发送 `SIGKILL`。不过这类选项我还是希望尽量放在“确认之后再用”的位置，而不是一上来就默认做得很激进。

## 还有两个我自己很常用的命令

除了查监听和结束占用，我平时还常用两个子命令。

一个是：

```bash
ports ps
```

![](https://img.alicdn.com/imgextra/i4/O1CN01gCdIPR1rgnGHLP0y8_!!6000000005661-2-tps-2406-1214.png)

这个更像是“开发者视角的进程一览”。除了 CPU、内存这些基本信息，它也会尽量给出框架线索，方便判断当前机器上到底跑着哪些开发服务。很多时候你不是卡在某一个端口，而是感觉机器上留了不少昨天没清理的东西，这时 `ports ps` 会比系统原生命令更接近日常使用习惯。

另一个是：

```bash
ports clean
```

它的目标不是“清理一切”，而是只针对内置白名单里的开发类运行时做孤儿进程清理，尽量避免误杀系统进程或普通桌面应用。

如果你经常同时起停多个服务，也可以直接用：

```bash
ports watch
```

它会进入一个实时刷新的 TUI 视图，端口新增、消失、切换都能直接看到。

## 命令速查

| 想做什么 | 命令 |
| --- | --- |
| 看本地常见监听 | `ports` |
| 查看全部 TCP 监听 | `ports --all` |
| 查看单个端口详情 | `ports <端口号>` |
| 结束指定端口占用 | `ports kill <端口...>` |
| 看进程列表 | `ports ps` |
| 清理开发类孤儿进程 | `ports clean` |
| 实时监控端口变化 | `ports watch` |

完整参数还是以 `ports --help` 为准，不过日常场景里，常用的基本就是上面这些。

## 为什么我会想把它做成 Rust CLI

这个工具用 Rust 写，原因并不复杂。

第一，它适合这种“高频、很小、希望立刻返回结果”的命令行工具。像查端口、扫监听、看进程这种动作，理想体验就是想到就敲一下，然后马上得到结果，而不是先等运行时启动。

第二，它适合分发。`Port Lens` 是一个单独的原生二进制，不依赖 Node.js 或 Python 运行时，下载之后放进 `PATH` 就能用。对这类基础开发工具来说，少一层依赖，使用门槛通常就会低一点。

另外，这种工具虽然不大，但会直接碰系统进程和监听信息。Rust 在错误处理和边界控制上的体验，也让我更放心一些。

## 适合谁用

如果你平时项目很单一，也很少在本地同时跑多个服务，那系统自带命令其实就够了。

但如果你经常在这些场景里切换：

- 前端项目同时起 `3000`、`5173`、`4321`
- 后端本地 API、数据库代理、调试服务一起跑
- Docker 容器和本地进程混合占用端口
- 昨天开的服务没关，今天继续撞端口

那 `Port Lens` 这种把信息先整理好、再把动作收拢起来的工具，会明显顺手很多。

## 安装方式

可以直接从 [GitHub Releases](https://github.com/heimanba/port-lens/releases) 下载对应平台的包，解压后放进 `PATH`，例如 `~/.local/bin/`。

如果你本身有 Rust 工具链，也可以自己编译：

```bash
cargo build --release
```

目前主要适用于 macOS，也支持 Linux。macOS 依赖系统自带的 `lsof`；如果机器上装了 Docker，它还会尽量关联容器名和端口映射，没有 Docker 也不影响核心功能。

## 小结

`Port Lens` 本质上是在处理一个很常见、但很少有人愿意专门优化的小问题：端口占用了并不难查，只是每次都查得有点烦。

我做它的目的，也不是为了替代所有系统命令，而是想把“看清楚谁占了端口，然后继续处理”这条路径压缩得更短一点。对我来说，一个顺手的开发工具，价值往往就在这种地方。
